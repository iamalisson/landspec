# landspec 2.6.0

## The independent review tries to break the change

The reviewer no longer only reads for bugs. It writes what the change claims, at most five claims,
builds one concrete counterexample for each (an input, a state already on disk, an ordering, a
caller) and follows it through the changed lines. The report lists each claim as `- held:` or
`- broke:`, and a broken claim is a finding.

- #177 the reviewer tries to break each claim, and tries to disprove a finding before reporting it;
  the report ends with one `Findings: <n> high, <n> medium, <n> low` line
- #177 the plan review checks **Reuse** (a task that adds what the repository or an installed
  dependency already provides) and the callers of code whose behaviour a task changes; the tasks
  template and `/speckit-tasks` search those callers too
- #177 `review.sh record` refuses an empty report file, one the reviewer named but never wrote

## A pull request costs fewer rounds

- #180 in `/landspec:implement` a fix round is reviewed as a delta, and as a full review only when
  the delta is refused (the branch was restacked, or the fix grew past 20 lines)
- #180 each implementer runs the scan and mutation testing before it returns, and is told what the
  reviewer and `pr.sh` check; `OPEN` runs them again only for a diff that has no record
- #180 `pr.md` runs the scan before the review, so its fixes are committed before the reviewer
  reads the diff, and records the file the reviewer names
- #180 an implementer that returns nothing has a rule: with a branch it is marked red and started
  again once, then failed (the count is shared with red test runs); with no branch it is failed at once
- #179 a green test run on a clean tree is recorded per copy, tree and test command, so `pr.sh` and
  `/landspec:implement` do not run the same tree's tests twice; a red run or a dirty tree always runs

## Measurements

- #181 the scripts append one line per step (task start, review recorded, implement mark and fail,
  test run, PR opened) to `.git/landspec-events`; nothing leaves `.git`
- #181 `bash .specify/extensions/landspec/scripts/stats.sh` prints one row per branch that opened a
  task or fix PR: minutes from start to PR (`?` for a fix PR or a task started in another
  clone, which have no start in this clone's log), review rounds, the first verdict, test time and the high and medium findings its reviews
  counted, then the totals

## Fixes

- #178 `setup.sh` stops before it writes anything on a branch behind a base that `origin` already
  has at a newer landspec, and says to run it from the base
- #178 the guard's refusal of a commit on a base branch says that a branch created earlier in the
  same command does not count; `/landspec:init` and the release steps run the switch on its own
- #178 `level.sh` fetches `origin` once, not once per long-lived branch
- #179 `pr.sh` adds a "Scanners not run" line to the PR body naming each scanner that was missing
  or failed; a crashed semgrep keeps its stderr in `semgrep.log`
- #179 each `mutants.sh` and `security-scan.sh` run gets its own report folder, so copies running
  them in the same second never share one

## Known issues

No full audit was run before this release. The independent reviews of its PRs left 0 high,
0 medium and 11 low (test gaps, wording, the local reuse of a green test run, local measurements).
They are tracked for the next release.

## Upgrading

`claude plugin marketplace update landspec && claude plugin update landspec@landspec`, then
restart Claude Code, and run `/landspec:init` in each project so its copy of the scripts is current.
Run it from the base branch: on a branch behind a base that already has the newer landspec, it now
refuses before writing anything.

No new keys in `landspec-config.yml`. A green test run is now reused for the same copy, tree and
test command: changing only git-ignored files (installed dependencies, `.env`) or the environment
does not run the tests again before the PR. CI still runs them.
