# landspec 2.10.0

## One branch and one pull request per feature (spec 008)

One PR for the whole feature (#265). There are no more GitHub issues, task branches or task PRs.

### A whole feature in one pull request (US1)

- `/landspec:implement` builds every startable task at once, each on a local task ref in its own
  copy, and lands it on the feature branch as a `--no-ff` merge with `Landspec-Task:` and
  `Landspec-Review:` trailers
- one draft PR opens after the first landing; it is marked ready only after the end check

### Progress without issues (US2)

- a task is done when its landing commit is on the feature branch; the PR body shows each task's
  state, review and landing commit

### One Opus review per plan and per task (US3)

- the plan review is one pass, and only high findings block
- each task gets one Opus review: high and medium block, one fix round re-checked by a delta review;
  lows are listed in the PR
- the guard refuses a reviewer on any model but Opus

### The end check before the PR is ready (US4)

- once every task is done: the tests and an Opus review of the branch against the spec; what is not
  met becomes new tasks on the same branch, up to `feature_rounds`
- once the feature PR is merged, `/landspec:implement` goes to the release and never reopens the
  branch or a second PR

### The existing gates hold, each run once (US5)

- tests run once per tree; the security scan and mutation testing run once, on the whole feature
  diff, before the PR is marked ready; a high scanner finding refuses it

### Moving to the new flow (US6)

- features started under the per-task flow stop with `LEGACY=` and the steps to finish them

## Upgrading

- Removed: `issues.sh`, `pr.sh task`, `pr.sh spec`, `implement.sh restack|stack|check-copy`,
  `branch.sh <feature> <task>`, the `review_model` key and the Simplify step.
- `branch.sh <feature>` makes the feature branch; `pr.sh feature [--ready]` opens the feature PR.
- New key: `task_rounds` (review rounds per task).
- Finish features started under the old flow with the steps `LEGACY=` prints.

## Not audited

The release audit (`/landspec:security`) was not run for this release, at the developer's call.
The code was reviewed by Opus per task and as a whole feature (three end-check rounds).
