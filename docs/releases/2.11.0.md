# landspec 2.11.0

Faster builds, and one security review per feature before its PR is ready.

## One security review per feature

- #274 the end check runs one security review of the feature's diff, at the same time as the
  feature review: it maps what the diff newly exposes, hunts only the categories that apply (with
  the scanners' output as leads) and tries to disprove each finding. A confirmed critical or high
  keeps the PR a draft. On a public repository the PR shows only counts and categories. The
  release reuses it, when it covers the merged PR's own last commit, in place of the
  whole-repository audit after the merge

## Faster builds

- #268 `tests/run.sh` runs the test files in parallel (`LANDSPEC_TEST_JOBS`, default: the
  machine's cores)
- #269 reviewers no longer evaluate the installed skills; implementers still do
- #271 `status` holds a task (`waiting REASON=shares <file> with <Tnnn>`) while an earlier task
  that can run or is running names the same file, so the two no longer meet in a landing conflict
- #267 the findings of a `ready` plan review are applied with a plan delta
  (`review.sh record --plan --delta`), not a new full plan review (#206)

## Fixes

- #272 no script or test pipes into `grep -q` under `pipefail`: the pipe failed now and then under
  load, and `remove.sh` could keep a managed file it should have removed
- #271 a ready task whose review check fails goes back to review, not to a full rebuild, and `land`
  shows the review's own refusal
- #270 `stats.sh` prints each task's time to land, its review rounds and its conflict round, and
  one line per feature
- #273 landspec's own `.specify` was reinstalled from source

## Upgrading

- New keys in `landspec-config.yml`: `security_review: on|off` (default `on`) and
  `release_audit: on|off` (default `on`).
- `pr.sh feature --ready` now refuses without a recorded security review
  (`review.sh record --security <report>`), unless `security_review: off`.
- New: `review.sh record|check|report --security`, `review.sh record --plan --delta`,
  `LANDSPEC_TEST_JOBS`.
- A task review report no longer has a `Skills:` line; an older report that has one is still
  accepted.
- `implement.sh audit-plan` can print `AUDIT=reviewed (…)` or `AUDIT=skipped (release_audit: off)`.
- Run `/landspec:init` again to update a project's installed copy.

## Not audited

The whole-repository release audit was not run for this release, at the developer's call. Each
change above had its own independent Opus review before its PR, and CI runs the suite on bash 3.2
with busybox, bash 5 with shellcheck, and macOS. The new security review has not yet run on a real
feature.
