# landspec 2.6.1

## What changed

- #185 a task's trailing `(depends on …)` clause is left out of its issue title, branch name and
  `next` text, so a dependency can be added or removed on a line that already has its issue: run
  the plan review again, then `issues.sh --sync` updates the issue's body

## Upgrading

`claude plugin marketplace update landspec && claude plugin update landspec@landspec`, then
restart Claude Code, and run `/landspec:init` in each project so its copy of the scripts is current.

An open issue created with the clause in its title, whose `— #N` was never written back to its
line, no longer matches by title: link it by hand (append ` — #N` to the line) or close it before
running `issues.sh` again. A task started before the upgrade whose short description plus clause
reached the branch name (`feat/005-t007-foo-bar-depends`) now gets a new branch name: finish it on
its old branch, or rename that branch to the new name first.
