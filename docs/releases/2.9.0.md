# landspec 2.9.0

## The AWS access layer (spec 006)

It is off by default; `/landspec:aws` turns it on with `aws: on`.

### A human deploys the agent's role; Claude never creates or changes it (US1)

- #207 with `aws: on`, the level writes `.mcp.json` for the AWS MCP server (pinned proxy release)
  and adds the "Cloud access" text to the constitution
- #208 the agent-role CloudFormation template and the lists of denied actions: dev builds, prod
  reads, and neither can delete data, stop audit, create users or keys, or change its own role
- #212 the optional organization policy, and `aws.sh setup --scp`, which prints how to attach it
- #251 the role trusts IAM Identity Center only (the `aws login` mode is dropped), the trust
  matches the permission set's role name exactly, and prod reads deny three more data reads

### Claude checks it works as the agent role (US2)

- #211 `/landspec:aws` and `aws.sh setup`, which configure the project and print the deploy
  command per account and the profiles to add
- #213 `aws.sh check`, which refuses any identity but the agent role, with `--simulate` to prove
  the denies
- #257 `aws.sh check` prints `PROD=none: no prod configured` when the project lists no prod
  profile

### The guard refuses destructive and prod commands (US3)

- #210 with `aws: on`, the guard refuses Terraform destroys, applies and AWS write verbs on prod,
  and reads of secrets, `.env` and state files

### Infrastructure PRs carry their Terraform plan (US4)

- #209 a diff touching Terraform needs a plan recorded for that exact diff, and the PR body shows
  its counts with stateful destroys and replaces first
- #254 a diff with only CDK, Pulumi or CloudFormation files says in the PR body that the plan gate
  was skipped
- #260 `docs/security.md` lists the plan gate as a layer of the security model

## Not verified in AWS

The layer was checked by its tests and by reading the template, not in a real AWS account: the
live run of the quickstart (deploying the role, the denied calls, the organization policy, the MCP
tool list) was not done. Run `aws.sh check --simulate` after deploying the role, and treat the
denies as unproven until it shows each one `denied`.

## Upgrading

`claude plugin marketplace update landspec && claude plugin update landspec@landspec`, then
restart Claude Code, and run `/landspec:init` in each project so its copy of the scripts is current.

- New command `/landspec:aws`, with the scripts `aws.sh` (`setup`, `setup --scp`, `check`,
  `check --simulate`) and `tfplan.sh` (`record`, `gate`).
- New config keys, all unset unless `/landspec:aws` runs: `aws` (default `off`), `aws_agent_role`
  (default `landspec-agent`), `aws_prod_profiles`, `aws_prod_paths` and `infra_dir`.
- With `aws: off` nothing changes.

## Known issues

The whole-feature check's last round left 2 items not met: the guard does not refuse a few prod
write commands that have no write prefix (listed in `docs/security.md`; the read-only prod role
still denies them), and the plan section with its stateful lines comes at the end of the PR body,
not at the top.

The release audit found 1 medium issue (access control), still to be confirmed, and 5 low ones
(input validation, configuration, access control, access control, supply chain). They are to be
fixed in a later release.
