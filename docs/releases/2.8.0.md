# landspec 2.8.0

## A `ready` plan review means every item was checked

- #231 the plan state hashes the whole feature folder, so a change to the data model, a contract
  or the research after a `ready` needs a new review; `record --plan` keeps a copy of what was
  reviewed, and the new `review.sh diff --plan` shows what changed since
- #232 the plan review runs as eight passes, each filling its own table, and `record --plan`
  refuses a `ready` that does not fill and pass them
- #235 the same change as #232, landed on `main` (#232 had merged into T001's branch)

## Fix rounds check the fix as new text, and a troubled area gets simplified

- #233 a plan fix round gets the last report and `review.sh diff --plan`, never the author's
  answers, checks each earlier finding in its own table, and tags each finding with its area
- #236 the same change as #233, landed on `main` (#233 had merged into T002's old branch)
- #237 each plan finding's area is counted across rounds; at 3, the next round opens with a
  `## Simplify: <area>` section and nothing goes out until `review.sh answer --plan` records the
  developer's answer

## The cost of the plan phase is visible

- #240 plan rounds log their findings, `issues.sh` logs its runs, `review.sh outside --plan <n>`
  records outside findings, and `stats.sh` prints one `PLAN` line per feature

## A delta review counts only the fix, not a merge of the base

- #228 a fix round's delta review no longer counts the lines a merge of the base brought into the
  task branch (git 2.38 or later; older git keeps the old count)

## A failed semgrep run names its real error

- #229 when semgrep fails with an empty log, the scan's line names semgrep's own error, read from
  its JSON

## Adopt warns about a formatter that would rewrite the existing code

- #230 `/landspec:adopt` runs each `.pre-commit-config.yaml` hook in a throwaway worktree with the
  new `formatters.sh` and warns when one would rewrite most of the existing files

## The skills and MCP tools a developer installed are used when a task fits them

- #243 implementers and task reviewers weigh the installed skills and MCP servers against each
  task and use the ones that fit; the PR's *Evidence* carries a `Skills:` line

## A PR is handed over only when it is mergeable and a Copilot review on it is answered

- #248 `pr.sh state <pr>` reports a PR's conflict, CI and Copilot state, and `--reply` answers and
  resolves one Copilot thread
- #249 a PR is listed to merge only when it does not conflict and Copilot's review is answered;
  Copilot's comments become a fix round, and each PR shows its CI state

## In progress

The AWS access layer (spec 006) is still not finished: its live verification in a real AWS
account (T007) has not run, so do not rely on it. It stays off until `/landspec:aws` sets
`aws: on`.

## Upgrading

`claude plugin marketplace update landspec && claude plugin update landspec@landspec`, then
restart Claude Code, and run `/landspec:init` in each project so its copy of the scripts is current.

- A plan recorded by 2.7.0 holds the old plan state hash (`tasks.md` and `plan.md` only), so it is
  reviewed again once.
- A plan review's `ready` must now fill the eight pass tables; a report in the 2.7.0 shape is
  refused.
- New commands: `review.sh diff --plan`, `review.sh answer --plan <area> <text>`,
  `review.sh outside --plan <n>`, `pr.sh state <pr> [--reply <thread id> [<file>]]` and
  `formatters.sh`. No config key changed.
