# landspec 2.7.0

## A dependency can change on a task that already has its issue

- #185 a task's trailing `(depends on …)` clause is left out of its issue title, branch name and
  `next` text, so a dependency can be added or removed on a line that already has its issue: run
  the plan review again, then `issues.sh --sync` updates the issue's body

## The weekly pin check waits for settled releases

- #184 `bin/check-tools.sh` reports a tool as behind only for the newest release that is not a
  prerelease or a draft and has been out for at least three weeks, the rule `pins.sh` already
  follows; a release younger than that no longer opens an issue the day it comes out

## A plan review counts only for the plan it read

- #186 a plan review is recorded only for the plan it read: the reviewer copies `plan.md` and
  `tasks.md`, hashes the copies with the new read-only `review.sh state --plan [<dir>]`, reviews
  them and writes `Plan state: <hash>`; `review.sh record --plan` refuses a report whose state is
  missing or no longer the plan's

## In progress

The AWS access layer (spec 006) is not finished: its files ship in this release, and all of it
stays off until `/landspec:aws` sets `aws: on`. Its live verification in a real AWS account has
not run yet, so do not rely on it; it is documented when it is released.

## Upgrading

`claude plugin marketplace update landspec && claude plugin update landspec@landspec`, then
restart Claude Code, and run `/landspec:init` in each project so its copy of the scripts is current.

- A plan report written before this version has no `Plan state:` line and is refused once: run the
  plan review again. A project whose plugin is upgraded but whose copy of `review.sh` has no
  `state` action gets `Plan state: unavailable` reports until `/landspec:init` updates it.
- An open issue created with the `(depends on …)` clause in its title, whose `— #N` was never
  written back to its line, no longer matches by title: link it by hand (append ` — #N` to the
  line) or close it before running `issues.sh` again.
- A task started before the upgrade whose short description plus clause reached the branch name
  (`feat/005-t007-foo-bar-depends`) now gets a new branch name: finish it on its old branch, or
  rename that branch to the new name first.

## Known issues

The release audit found no critical or high issue. It found 3 medium issues (guard bypass, guard
bypass, secret exposure) and 7 low ones (insecure design, secret exposure twice, access control,
configuration three times). They are to be fixed in a later release.
