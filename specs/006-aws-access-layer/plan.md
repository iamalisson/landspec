# Implementation Plan: Safe AWS access for Claude Code

**Branch**: `spec/006-aws-access-layer` | **Date**: 2026-11-16 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/006-aws-access-layer/spec.md`

## Summary

One opt-in layer, `aws: on`, set by a new command `/landspec:aws` (`skills/aws/SKILL.md` over
`extension/scripts/aws.sh`). It ships a CloudFormation template the human deploys per account: an
agent role trusted only by an Identity Center permission set (research R2), read-only in prod and
on lite, `PowerUserAccess` in dev (which grants no IAM write but service-linked roles), with an explicit deny of destructive, audit,
key-creating and self-editing actions, and in read mode of secret and data reads (R6). The same
command checks the identity (`assumed-role/landspec-agent` passes; a user ARN or another role is
refused) and, with `--simulate`, proves the denies with the read-only IAM policy simulator (R10).
With the layer on, the existing guard also refuses Terraform destroys, prod applies and prod writes,
secret reads and printing `.env`/state files; the existing PR gate on standard and full requires a
Terraform plan record for a diff that touches `.tf` files (`tfplan.sh`, R11). landspec runs no AWS
write and adds no command that does AWS work.

## Technical Context

**Language/Version**: bash 3.2+ (BSD, busybox, GNU); markdown prompts; one CloudFormation template (YAML, long-form intrinsics) and one SCP (JSON).

**Primary Dependencies**: existing git, gh; at run time, only in projects with the layer on: AWS CLI v2 (≥ 2.32 for `aws login`, any v2 for `aws sso login`), `uvx` for the MCP server, Terraform or OpenTofu for the plan gate. `python3` optional (JSON plan; text fallback).

**Storage**: config keys in `landspec-config.yml`; the plan record under `<git common dir>/landspec-tfplan/` (data-model).

**Testing**: `tests/run.sh`; new `tests/aws.test.sh`, `tests/tfplan.test.sh`; added checks in `guard`, `pr`, `level`, `static`, `remove` tests; fake `aws` and `terraform` in `tests/helpers.sh`, like the fake `gh`. Live checks in quickstart Q1–Q6 by the maintainer.

**Target Platform**: Linux and macOS, where Claude Code runs; AWS accounts with IAM Identity Center.

**Project Type**: Claude Code plugin plus spec-kit extension.

**Performance Goals**: the guard stays within its hook budget: the AWS rules add no subprocess per command (no AWS call; config read once).

**Constraints**: no AWS write by landspec; nothing of the user's overwritten (`.mcp.json` and `.claude/settings.json` only when missing); projects with `aws: off` unchanged (SC-005); pins at releases a few weeks old.

**Scale/Scope**: 1–2 accounts per project (dev, prod); one region per stack.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| A non-bash artifact (CloudFormation YAML) in the extension | the role must exist before the agent can do anything, deployed by a human, removable as one unit (R5) | a bash script of CLI calls leaves partial resources on failure and cannot be removed as one; Terraform needs a state bucket the role would have to create first |
| A second record kind beside review and scan (`landspec-tfplan`) | FR-012 binds the plan to one exact diff | putting plan counts in the review report would let the author write them by hand |

## Risks

- **`aws login` trust (R3) is unverified.** Outcome: Q2 was not run, so `login` mode was dropped (T007, #251) and Identity Center is required. Planned: `login` mode ships only if quickstart Q2 passes; the
  default and documented path is Identity Center either way.
- **The guard's prod detection only sees declared names.** A prod write through a profile not in
  `aws_prod_profiles`, or the default profile pointing at prod, is not caught by the guard; IAM is
  the boundary (prod role is read-only), and the docs say so.
- **The plan record binds to the diff, not to the plan's tree** (data-model, "Plan record"): a
  plan older than the last commit or made with uncommitted `.tf` edits is refused; a plan from
  another checkout is not detected.
- **The agent acts only as itself** (data-model "Invariant (the agent's reach)"): no IAM write, no
  `PassRole`, no `AssumeRole`, so its inline deny is on every call it makes. Outside it: running
  code inside an existing workload whose role is stronger (`lambda:UpdateFunctionCode`,
  `ssm:SendCommand`, a CodeBuild override); neither the deny nor the SCP covers that, so the docs
  ask for a dev account with no such workload, and no stack with a service role the agent could
  update. Terraform that adds IAM goes through a PR and the pipeline, never the agent; and since the
  agent cannot pass a role, applies in dev are limited to resources that take no role (no Lambda, ECS task, EC2 instance profile or other resource that is handed a role); anything with a role goes through the pipeline.
- **MCP tool list drift** (`call_aws` removed): the allow and ask lists name tools; a renamed tool
  falls back to Claude Code's default prompt, never to allowed.
